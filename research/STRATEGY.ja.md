## 1. 診断：インラインの後に何が残り、なぜ残るのか（measured）

999 規則の内訳（`probes/survivors.py`）：サイトの欄 270、部分式 X 171、条件 K 169、young のレジスタ約 300、old のレジスタ
約 60、ヘルパ 29（`Code_c` 21 本すべてと `Tail_c` 8 本）、フォールバックと制御器で約 16。

compact 版での展開費用（被参照数 ×（大きさ − 1））：young レジスタは被参照数の中央値 64（最大 201）・大きさ 28、サイト欄は
38（最大 931）・17、X は 1・89、K は 3・2。展開費用の上位 1,000 は young レジスタ 255、サイト欄 318、X 326、old レジスタ 51。
原因はポインタの読み出し：`Fld(x, f)` は x の領域のサイトごとの分岐 `&(x_c Tail_c) x_ext C_s_f` になるので、**レジスタの被参照数
≈ 欄の読み出し回数 × 領域のサイト数**で、領域には young 層ごとに 1 サイトある（色 21 = IN 2 + young 15 + old 4 の FIFO サイト）。
young 層を減らすと、層の数と、残る規則すべての展開費用の両方が下がる。

ほかに 3 つ：

- **貪欲インライナが実用上の限界線**（`probes/keep_policy.py`）。レジスタ・サイト欄・ヘルパ・フォールバック・制御器だけ残して
  K と X を全部展開すると N 945 で 1.2 億ノード（×613）、被参照数の閾値で残すと 10³⁸ ノードに爆発する。貪欲は ×16 で N 946。インライナは手ではない。
- **床の削減は ×2〜×4 の N に 6〜7.5 割で効く**（16/4 → A：床 −238 で ×2 −172、×3 −150。`noacc fuse compact` → A：床 −71 で
  ×2 −55、×3 −41）。×4 で 1,000 未満には約 −121（床で約 −160〜−200）、×3 なら約 −195（床で約 −260〜−325）が要る（estimate）。
- **21 本の `Code_c` は絶対に消えない**：`Code_c = &Tail_c / . Code_c` は自分を参照し、インライナは自己参照規則を消さない。

## 3b. S3 と S2′ の実装（measured）

### S3：anchor の釣り合い → young 15 → 13

`OverlapPal.Sched(num, den)`（β = num/den。`pool-grid`・`overlap-profile`・`lps-code` に `beta=7/16`）。β = 1/2 は元の制御器
そのもの（既定の文法は sha256 が変わらない）。(1/3, 1/2) のそれ以外の β は制御器に**段つき時計**を入れる：各 2 冪の tick P
（W₀/2 から）で walker `clk` が、保存した 2 冪セル P/2^j（2 冪の tick ごとにずれる履歴 `h1 … hJ`）から順に歩き切り、3 つの
区間の終わりが事象になる。(2 − 2β)P で `cA` が次の A の replay セルを保存、(1 + β)P で B 族が誕生（A が young の間だけ、`ya`）、
4βP で `cB` が次の B の replay セルを保存。段は区間 (1 − 2β)P、(3β − 1)P、(3β − 1)P の 2 進の桁で、7/16 なら
P/8 | P/4 + P/16 | P/4 + P/16（5 段、W₀ ≥ 32）。replay は正確（k_A = (1 − β)W、k_B = 2βW）。変わるのは制御器と IN だけで、
コアは変わらないので層あたりの費用は増えない。`AnchorSchedSuite`（measured）：段とアンカー、β = 1/2 で元の制御器、モデルが
7/16（W₀ 32）と 3/8（W₀ 16）でオラクルと一致しプロファイル（誕生・replay セル・答える族）がきれい、役割機械が 7/16 で strict な
役割プロファイルもきれい、コード backend でアンカー 32・46・64 をまたいで PEG の規則が interpreter と一致。

young 窓の 1 tick あたりの文字数（A = 2/(α−1)、B = 2α/(2−α)）：α = 3/2 で 4 と 6、23/16 で 4.57 と 5.11、11/8 で 5.33 と 4.4。

### E2 と S2′：不一致の歩が自分の gap を展開する

E2（`StepKinds` の「GNODE pushes」。役割 15/4 A から `fuse` を外し、W₀ 32）：`GNODE(cur, L)` を積む不一致は、乱数語（400 語 ≤ 1,025）で
young の busy な歩の 9.2%、old の 8.3%、adversarial（≤ 600）で 0.3% と 0.1%。どれも次は必ず `gPopG` なので、S2′ で減るのはちょうどこの歩。

`GapKmp.Core(unfold)`（`unfold` フラグ）：不一致の歩が `LNODE(cur, L)` と `KNODE(LNODE, K, cur.hR, cur.hK)`（遷移は K ノードの
サイトを使わない）を作り、`L := cur.hL` とする。`UnfoldSuite`（measured）：全語 ≤ 10 でオラクルと一致、switch/structured ≤ 129 で
プロファイルがきれい、旧 backend（≤ 6）とコード backend（構成 A、1/1 で ≤ 12、2/2 で ≤ 11）で PEG = interpreter、GNODE はもう
積まれない、構成 A + unfold の strict な役割プロファイルがきれい。モデルのレート（β 7/16、大きな集合）：12/12/4 不合格（n 71）、
**12/12/5 合格、13/13/3 合格**。n = 71 の語で、`endonce` ありの役割機械は unfold 付きの 13/4 と 13/3 で通り、12/5 と 12/4 で落ちる。

### 全長さの語族と、POOLS の文法の誤答

POOLS とこの節のレート探索は、4 語族（乱数、adversarial、switch、structured）を 3 つの種で回していた。switch 族はアンカーの
まわり（bOf(W)、2W、2bOf(W) ± 1）で作り、`probes/runner_words.py` は長さを倍々に飛ばすので、どちらもすべての長さには届かない。
`OverlapProfile.everyLengthWords`（`pool-grid … every=<maxLen>`）は runner の 7 種の語（`b a^(n-2) b` とその反転、Thue–Morse
回文と n/3 の反転、周期 3、`a^i b a^j b a^i`、乱数回文）を長さ 3 … maxLen の**すべての長さ**で作る（1,025 までで 7,158 語）。

**POOLS の役割機械（15/4 A、β 1/2、W₀ 32）はこれに n = 79 で落ちる**：最初の B 族（h 48、young 窓 16 tick）の B が、79 文字の
乱数回文 `bbbabaabaaaaabaaaaabbababaaaabaaaaaabbaaabbaaaaaabaaaabababbaaaaabaaaaabaababbb` の終わりまでに追いつかない。
そこから作った 999 規則の文法は 2 つとも（main の `out/pools-role-y15-o4-n999.peg.gz` と E1 の
`out/pools-role-y15-o4-star-n999.peg.gz`）、Rust runner でこの語に **false** を返す（measured）。原因：`endonce` は構築を終えられる
のを 1 tick の最初の young 歩だけにするので、young 窓が 1 tick を失いうる。最短の窓では引き継ぎが遅れ、old 4 では追いつけない
（`endonce` なし、W₀ 64、old 5、young 16 ならこの語は通る）。3 つの種にはこういう語が入っていなかった：検証は有限の観察で、
これを見逃していた。

## 4. handoff のほかの路線（この数字で見直し）

- **最悪 O(1) の連結可能デック（handoff §4.4）**：レートを決めるのは乱数回文での仕事の総量（スループット）で、pop の突発では
  ない。実時間デックは 1 操作あたりの仕事も層あたりの欄・サイトも増える。勧めない。
- **割り当てサイトの由来解析（§5）**：セルは tick を越えて生きるので、レジスタの領域は全 young 層にわたる。健全な解析で刈れる
  のはその tick に生まれたセルだけ。作る前に読み出しごとの実際のサイト集合を測る。効果は小さい見込み。
- **端点の切り詰め（§6）と eertree（§7）**：障害は変わらない（`D^k` は閉じない、不変の記述子は後で作る回文を指せない）。
- **2 文字の構築ステップ**（entry の対）：構築の割り当ては半分になるが ENTRY の領域が倍（色 +15、ヘルパ +30）。S1〜S4 の後、測って得があるときだけ。
- **young ステップあたりの割り当てサイトを減らす**ことが ×2 に要る：young の 1 歩は list ノード・entry・stack ノード・rear ノード・
  FIFO セルを割り当てる（census で層あたりサイト欄 18）。gap マッチャの O(1) の歩を保ったまま種類を減らす構成は知られていない。
  これが ×2 の背後にある未解決の設計問題。
