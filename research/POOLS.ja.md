# 構築役と回答役：役割プールによる PAL の PEG（2026-09-25）

`inst.md`（プール計画）を main `0a2d58f`（`UNDER1000.md` の gap core）の上で実行した記録。英語版 `POOLS.md` が正本で、
ここはその日本語版。すべて印刷された文法とインタプリタ上の実験で、**Lean の証明ではない（`../proof` の定理は
オートマトンについてのもの）**。数値は *measured*（書き出した文法・インタプリタ・プロファイラの実測）、*estimate*
（明示した費用の和）、*target* のどれかを付けて書く。

## 0. まず UNDER1000.md の訂正

**10/13 の文法は長さ 128 の回文で誤答する（measured）。** Task 0 で 4 番目の語族として乱数回文・準回文
（`OverlapProfile.randomWords`、種 21）を足したところ、200 語（長さ ≤ 513）の 87 語目、長さ 128 の回文で、bank B
（anchor h = 96、初回答 128）が最初の回答 tick に追いつかず false を報告した。インタプリタも、マージ済みの 2 つの文法
（`out/under1000-gap-a10-b13.peg.gz` の 5,902 規則版と、そのインライン 1,492 規則版）も Rust runner で **false** を返す。
この語は `PoolsSuite` に残した。前回の検証は乱数語 60 本（長さ ≤ 129）だけで、この場合に届いていなかった。B = 14 に
すると 4 語族すべてに合格する（乱数 2,000 語 ≤ 1,025、adversarial ≤ 600、switch ≤ 1,025、structured ≤ 1,025、計 3,385 語）。
訂正版の現状は **10/14 = compact 6,177 規則**（measured。色数 17 で W₀ = 32、機械の初回答は 24 から 48 に移る）。

以後のレート探索では、乱数語族を必ず数千語・長さ 1,025 まで入れ、最終候補は別の種で長さ 2,049 まで確かめた。

## 1. 歩の需要（Task 0、measured）

各 tick・各 bank で、その bank のレジスタを変えた最後の万能歩コピーの番号を数えた（コピーは決定的なので、最初に
何もしなかったコピー以降はすべて何もしない）。最初の回答 tick より前を young、以後を old とする。10/13・minAnchor 16
では、4 語族とも young A 10、young B 13、old 最大 13（最初の回答 tick で 13）。young はビルドの材料が誕生時点で全部
そろっているので、与えられた歩をすべて使う（40/40 でも 40 を使う）。old は大半の tick で 1〜2 歩だが、10 と 13 に
裾がある：young bank が最大 178 文字の backlog と pop の途中状態を引き渡すため。

**Gate 0：** k_o = 13 > 6 なので Task 6（小さい old プールの遅延応答）を先に行った。inst §2 の前提「young になった
時点の FIFO は高々その tick の 1 文字」は偽（measured backlog ≤ 178）。

## 2. old 制限モデルと役割機械（Task 6 と Task 1）

**モデル。** `OverlapPal.machine(a, b, W₀, GapCore, oldLimit = O)` は、bank が old の間は万能歩の最初の O コピーだけを
動かす（young ⇔ family A なら `clk` が武装中、B なら非武装）。a = b = Y とすれば、役割機械（young プール Y、old プール O）
と同じ歩の予算を bank ごとのレジスタで再現できるので、役割機械を作る前にレートを探せる。`pool-grid` は 4 語族を
並列に、最初の違反で打ち切りながら調べる。`strict` は引き渡し条件（young 窓の終わりまでに BUILD/REV を出ている）を足す。

**役割機械**（`RolePal.scala`）。レジスタ `y_*`（young：gap core 全体、パターン源、リプレイのカウントダウン、FIFO）と
`o_*`（old：照合専用の gap core と FIFO）、タグ集合は 1 つ。スケジュールは `CT, IN, YU × ky, OU × ko, OUT`。`IN` は
引き渡し（誕生時に `o := y`）→ young のリセット／push → old の push を `Lpm.fuse` で合成。`IN` の FIFO 割り当ては役割
ごとに 1 サイトに共有。`OUT` は `o_acc` を答える。`GapKmp.Core(matchOnly)` は BUILD/BPOP/REV と entry/rear サイトを
持たない。既定の core は変えていない（書き出した 10/13 文法の sha256 が不変、`RolePalSuite`）。

テスト（measured）：16/8 で全語 ≤ 10 が期待出力と一致。RolePal(14, 4, 16) とモデル OverlapPal(14, 14, 16, oldLimit 4) は
4 語族の 666 語で tick ごとに同じ出力、役割版プロファイル（strict、引き渡しの完全コピー）も無違反。`LpsCode` 経由の
PEG = インタプリタ（1/1、minAnchor 4、全語 ≤ 10、`checkRules`・`checkReachable`）。W₀ = 16 のウォームアップ境界。

## 3. レート（measured、`pool-grid`）

| young / old | 乱数 400 ≤ 513 + 3 語族（1,785 語） | 乱数 2,000 ≤ 1,025 + 3 語族（3,385 語） |
|---|---|---|
| 13 / 3 | 乱数 400 語中 42 語で失敗 | — |
| 14 / 4、14 / 6、14 / 8 | 合格 | 失敗（n 65、n 262・h 192） |
| 15 / 3 | 合格 | 失敗（n 671・h 384） |
| 15 / 4、15 / 5、15 / 6、16 / 3、16 / 4、17 / 3、18 / 4 | — / 合格 | 合格 |

- **young 14 は old をいくら増やしても失敗**：B の young が大きすぎる backlog を渡し、old が次の回文の終わりまでに追いつけない。
- **old 3〜4 は young が十分速ければ足りる**。old は長い区間遅れている（最大 128 tick 連続）が、完全一致が起こりえない
  間は遅れても害がなく、不一致のあとの次の完全一致は pop の費用と同じだけ先にある（KMP のポテンシャル）。有限の観察で証明ではない。
- **構成 A**（`r15/4:noacc,fuse,compact,endent,endonce`、§4.2）：大集合で 15/4・16/3・16/4 合格。
- **レート探索は本番の W₀ で行う必要がある。** 種 7 を minAnchor 16 で回すと A は n = 42（B、h = 24）で落ちるが、本番は
  色数 21 で W₀ = 32 なので最初の anchor は 32、長さ 48 未満はフォールバックが答える。命の仕事は入力だけで決まるので、
  長さ ≥ 48 の語は minAnchor 16 と 32 で同じ振る舞い。minAnchor 32 では A は新しい種（3,810 語、乱数 ≤ 2,049）に合格し、3 つ目の種 11（乱数 5,000 語 ≤ 2,049 + 3 語族、計 6,385 語）にも合格（16/4 も合格）。
- **base-3 時計（W₀ = 24）は使わない。** 倍々の時計を tick 3 から始めると anchor は 24, 36, 48, 72, … で、21 色なら W₀ = 24
  で足りる。A は minAnchor 24 の大集合に合格したが、新しい種で n = 197（B、h = 144）に落ちた。anchor の並びが変わると
  別の語が縁に来る。インライン後はフォールバックはほとんど消える（§4.3 で 4 規則）ので、オプションとして残すだけにした。

## 4. 結果

### 4.1 Gate 1：role 16/4（measured）

compact 4,987、インライン ×1.25 1,972、×2 1,549、×3 1,344、×4（最大 RHS 16,384）1,280 で、1,150 を超えたので inst の規則
どおり census を層ごとに比べた。young 層は元の万能歩と同じ（core 50：ポインタレジスタ 10 本 × 2、`src`・`rc`、ビット 7、
サイト欄 21）、old 層は core 39、IN は引き渡し込みで 57、層 0（前 tick の値）66、フォールバック 50、ヘルパ 44。inst の見積り
（13/3 でインライン後約 1,070）が外れた理由：必要なプールが 13/3 ではなく 16/4 か 15/4（young +3 層、old +1 層）、層あたり
core が 46 でなく 50、old の FIFO の領域（IN の 2 サイト + すべての young・old 層）で 22 色になり W₀ = 32。

|---|---:|---|---:|---:|---:|

`tmp` と `rk` が損な理由：色は 1 つのポインタ式が指しうるサイト集合ごとに単射でなければならず、どちらも 2 つのタグに
またがる式を作る（`Fld(tmp, 1)` は rear なら entry、stack ならリスト）ので 34〜38 色、W₀ 64 になる。

`endonce` が正しい理由：young の本文は最初の回答 tick までパターンより短いので、young は完全一致を起こさず `end` を読ま
ない。読むのは old だけ。`endonce` ではビルドが後のステップで終わった young は次の tick の最初のステップまで待ち、strict
検査が「引き渡し前に END ができている」ことを保証する。1 つの命につき最大 1 tick 分の損なので、レートは測り直した（§3）。

### 4.3 結果：N < 1,000（measured）

`lps-inline-curve` は貪欲インライナを最大予算で 1 回走らせ、消去ごとに (N, ノード数, バイト) を記録する。最大 RHS を
固定すれば、小さい予算での消去列は大きい予算での消去列の接頭辞なので、1 回で曲線全体が得られる。構成 A（compact
4,216 規則、`out/pools-role-y15-o4.peg.gz`）、最大 RHS 65,536：

| ノード予算 | N | RHS ノード | バイト（推定） |
|---|---:|---:|---:|
| ×2 | 1,377 | 398,621 | 1.92 MB |
| ×3 | 1,194 | 596,775 | 2.79 MB |
| ×4 | 1,120 | 796,230 | 3.51 MB |
| ×8 | 1,023 | 1,582,180 | 6.71 MB |
| **×9.75** | **999** | **1,945,495** | 8.21 MB |
| ×16 | 946 | 3,179,139 | 13.8 MB |
| ×32 | 878 | 6,346,794 | 26.6 MB |

**999 規則の文法**（`out/pools-role-y15-o4-n999.peg.gz`）：999 規則、RHS 1,945,495 ノード、最大 RHS 16,224、7,958,678 バイト、
DAG ノード 42,936、gzip 275,293 バイト。sha256：`.peg` `eef35388…77656c1`、`.peg.gz` `102db800…108f0a958`。検査：再パースして
全 1,023 語 ≤ 9 でオラクルと一致、Rust runner で 140 語（24〜601 文字）不一致 0（1 語最大 4.4 秒、6,700 万歩）。
元の機械（RolePal 15/4 A、W₀ 32）は 3 つの種の 4 語族（3,385 + 3,810 + 6,385 語、§3）と、却下した構成すべての反例に正答する（`PoolsSuite`）。

inst の目標（`PegOptimize` + 予算付きインライン後に N < 1,000）は満たすが、**望ましいサイズ（×2〜×3）では届いていない**
（×2〜×3 では 1,377〜1,194 規則）。999 規則版で残るのは、次の層から何百回も読まれる規則：ポインタレジスタは色ごとの
分岐で読まれ、ガードは層のすべてのレジスタ更新で共有される（`y_K_5` は参照 680、`y_q0_5` は 860）。
